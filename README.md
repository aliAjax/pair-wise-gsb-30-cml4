# 油品配送计划 · 夜间离线装车闭环

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`

数据默认保存在浏览器 localStorage 中，方便后续扩展接口、权限、图表或地图能力。

## 解决的问题

油站夜间断网，调度员/司机只能先改本地配送单；网络恢复后旧车次容易被重复发送。
本项目把 **配送计划、车辆容量、离线装车批次** 三者接通，形成闭环：

1. **离线暂存（按车次）**：断网时司机装车只写本地批次，记录回执号、车次、车牌、实装吨数，
   以及装车时依据的**计划版本快照**，不触碰在途计划。
2. **恢复合并（版本 + 车牌）**：网络恢复后逐批与最新计划比对——
   - 计划版本与快照一致且车牌一致、吨数不超容量 → 合并、计划版本 +1、确认发车；
   - 计划已在途（运输中/已到站）→ 一律拒绝覆盖与重复发车；
   - 车牌已被**另一名调度员改派**、或实装吨数 **超过车辆容量** → 批次进入**冲突台账**，
     本地批次保留留痕，在途计划不被覆盖，也不确认发车。
3. **回执幂等**：每个装车回执号只处理一次——无论是历史已处理（幂等表）还是同一次同步中重复出现，
   旧车次再发一遍都会被标记“重复跳过”，不会让计划重复升版或重复发车。
4. **冲突处理后重算**：调度员在台账中处理（批次换车/改吨、扩容车辆或作废回执）后，
   按最新计划重新比对；通过才合并发车。改派差异必须由调度员在台账显式换车确认，
   不能一键覆盖同事的改派；在途计划即使重算也继续拒绝。

## 界面与演示路径

- 顶部「模拟网络恢复并同步 / 模拟断网」切换联网状态，恢复时自动合并。
- **配送计划**：查看车次版本、车牌、容量、状态；「模拟他端调度员改派 PC-1004」复现夜间他人改派。
- **离线装车批次**：断网时录入装车信息按车次暂存；相同回执号可验证幂等。
- **冲突台账**：展示超容量 / 已改派 / 已在途等冲突原因，支持换车改吨、扩容车辆、按最新计划重算、作废。
- **车队与日志**：维护车辆核定载量；同步与处理全程留痕。

预置数据已包含一条重复回执（HK-5001）、一条超容量（16 吨 > 京B·2002 的 15 吨）、
一条撞在途（PC-1003）与一条等待他端改派（PC-1004），直接点「恢复并同步」即可走完整条链路。

## 关键模块

- `src/types.ts`：计划（含版本号）、车辆容量、离线批次、冲突台账等领域模型。
- `src/mergeEngine.ts`：纯函数合并引擎——幂等去重、冲突检测、处理后重算（可独立单测）。
- `src/stores/delivery.ts`：Pinia 状态、localStorage 持久化、断网/恢复同步与冲突处理动作。
- `src/App.vue`：四个页签的调度操作界面。
