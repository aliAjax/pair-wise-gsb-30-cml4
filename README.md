# 油品配送计划 · 夜间离线装车与恢复合并

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 核心逻辑自测：`node test/run-tests.mjs`（或见下）

## 解决的问题

油站夜间断网，调度员只能改本地配送单、司机只能离线装车；网络恢复后旧车次容易被重复发送，
且夜班里另一名调度员可能已在服务器端改派车辆，本地批次还可能超过车辆容量或撞上已在途计划。

本项目把「配送计划版本、车辆容量、离线装车批次、冲突台账、回执幂等台账」接成一条闭环：

1. **离线按车次暂存**：断网时调度员可改本地配送单（车牌/吨数，只动本地缓存版本），
   司机装车生成 `LoadingBatch`，记录车次号、车牌、实装吨数、所依据的计划版本 `baseVersion` 和装车回执号。
2. **恢复后按「计划版本 + 车牌」合并**：联网（或手动点「立即同步合并」）时执行 `runSync`，
   以服务器最新计划为准逐批评估（`src/lib/sync.ts` 中的 `evaluateBatch`）。
3. **同一回执只处理一次**：已处理回执进入幂等台账；恢复后旧车次再发一遍会标记为「重复跳过」，
   不二次合并、不二次发车。
4. **冲突进台账，不覆盖在途计划，也不能发车**：
   - `reassigned` 车辆已被另一名调度员改派（计划车牌 ≠ 本批车牌）
   - `over_capacity` 实装吨数超过本地车或计划改派后车辆的额定容量
   - `in_transit` 车次已发车/到站，在途计划不可覆盖
   - `trip_missing` 最新计划中该车次已取消
   - `vehicle_unknown` 车牌不在车辆台账
5. **处理完冲突按最新计划重算**：冲突台账中可选择「跟随最新车牌改派 / 减量到容量内 / 作废本地批次」，
   提交后重新跑同一套评估；仍冲突则继续留在台账，无冲突才合并。
6. **确认发车是最后闸门**：只有 `merged` 批次可发车；发车瞬间再按最新计划校验一次，
   若处理冲突期间车辆又被改派，批次自动退回冲突台账，绝不误发在途车次。

## 页面页签

- **离线批次与同步**：离线装车暂存表单、批次列表（本批车牌/最新计划车牌/发送次数/状态）、同步与确认发车
- **配送计划（版本）**：切换查看本地缓存版本（离线可编辑）与服务器最新版本；在线时可「模拟他人改派」制造冲突
- **冲突台账**：未处理冲突的改派/减量/作废处理表单，以及已处理记录
- **回执幂等台账**：每个回执的发送批次数与处理结果
- **同步日志**：断网、改单、暂存、同步冲突、发车的完整时间线

种子数据覆盖全部场景：T1001 干净合并、T1002 改派+超容量、T1003 在途、
T1004 改派、T1006 车次已取消、T1001 同回执重复发送。右上角「重置演示数据」可恢复夜间断网初始场景。

## 推荐演示路径

1. 初始为断网状态，在「离线批次与同步」里可继续暂存装车；在「配送计划（版本）」本地版本里改车牌/吨数。
2. 切换到在线（右上角开关），自动执行同步：1 车合并、4 车进冲突台账、1 条重复回执被跳过。
3. 打开「冲突台账」逐条处理：T1002 可跟随新车牌并减量、T1003 在途只能作废、T1006 车次缺失只能作废。
4. 回到批次页对「已合并待发车」批次点确认发车；在线时再去计划页模拟一次改派，
   可看到未发车批次在发车闸门被拦截并退回台账。

## 自测

```bash
node test/run-tests.mjs
```

覆盖：干净合并、改派/超容量/在途/车次缺失冲突、回执幂等（含二次同步重放）、
冲突改派/减量/作废重算、发车前再校验与防重复发车，共 11 项断言。

数据默认保存在浏览器 localStorage（key：`hxwlfront-19-oil-sync-v1`），
方便后续扩展服务端接口、权限与实时推送能力。
